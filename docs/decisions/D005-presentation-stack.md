# D005 · 先升级网页表现层，不立即迁移游戏引擎

## 目的

让原型具有场景、节奏、声音和动作反馈，同时保留低门槛分享、匿名记录和快速改规则的能力。

## 当前决定

v0.7 继续使用原生 HTML、CSS 和 JavaScript，增加原创场景图、程序化音景、剧情舞台和游戏化调研包装。核心模拟状态与表现层继续分离。

## 为什么现在不迁移

- **Ren'Py** 很适合角色立绘、对白和镜头演出，但当前玩法还有证据板、时间池、认知云图和研究者观察台，网页实现与测试成本更低。
- **Godot** 是中期最值得考虑的引擎，适合进一步加入场景探索、角色走位、时间轴动画和更强的音频控制，也能导出 Web；但当前核心循环还没有经过足够真实用户验证。
- **Unity** 的团队协作、3D和商业生态很强，但对这一阶段的二维认知剧情原型过重，会把时间消耗在工程和资源管线上。
- **Twine / Ink** 适合大量分支文本与叙事脚本管理，可以以后作为内容层参考或接入；单独使用难以覆盖当前模拟面板与研究流程。

## 重新评估迁移的条件

满足以下至少两项时，再制作 Godot 技术样片：

1. 两轮真实测试证明“探索—假设—行动—反馈”本身有吸引力。
2. 玩家明确需要在场景中走动、观察物件或调动人物，而不只是更漂亮的卡片。
3. 内容制作已经被网页模板拖慢，镜头、角色动画和音频状态成为主要工作量。

迁移时先只复刻一个完整场景，并让网页版本继续承担用户测试与数据分析，不重写全部内容。
